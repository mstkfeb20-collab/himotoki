次の設計書を読み、実装の手順ではなく「守りたいもの」を抽出してください。

対象: samples/spec-extraction/docs/ のすべてのファイル（Word・Excel）

## 抽出するもの

設計書は「どう作るか（手順）」で書かれています。その手順が**なぜ必要か、何を守るためか**を取り出してください。

| 種類 | 意味 | 例 |
| --- | --- | --- |
| 不変条件 | どんな処理の後でも常に成り立つこと | 残高はマイナスにならない |
| 事前条件 | 処理を受け付ける条件 | 取消は出発日の前日まで |
| 事後条件 | 処理の後に必ず成り立つこと | 振込済の取消では返金する |
| 状態遷移 | 状態の進み方の制約 | 取消済は終端で、他の状態に戻らない |
| 順序制約 | 処理の前後関係 | 出力ジョブの正常終了後に送信ジョブを実行する |
| 業務ルール | 計算・判定の決まり | 取消料率は出発日に近いほど高い |

## 抽出しないもの

- 手順そのものの言い換え（「画面に戻る」「メールを送信する」など、守りたいものを含まない手順）

## 質問にするもの

設計書だけでは判断できない点は、推測で埋めずに質問として出してください。

- 文書内・文書間の矛盾（本文と改訂履歴で値が違う、別の設計書と整合しない など）
- 条件の書かれていない例外（「原則として」「この限りでない」など）
- 設計書が前提にしているが、どこにも定義されていない項目

## 出力形式（JSON）

```json
{
  "rules": [
    {
      "id": "R-01",
      "kind": "不変条件 | 事前条件 | 事後条件 | 状態遷移 | 順序制約 | 業務ルール",
      "statement": "守りたいものを1文で",
      "sources": ["ファイル名 章・シート・行"],
      "confidence": "高 | 中 | 低",
      "suggested_layer": "設計 | Lint | テスト | 実行検証 | 文章"
    }
  ],
  "questions": [
    {
      "id": "Q-01",
      "type": "矛盾 | 曖昧 | 根拠不足",
      "statement": "何が判断できないか",
      "sources": ["ファイル名 章・シート・行"]
    }
  ]
}
```

採点: `python eval/spec_extraction/score.py <出力.json> --detail`
