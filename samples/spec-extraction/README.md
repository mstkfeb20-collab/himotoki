# 設計書からのルール抽出 検証用サンプル

既存の設計書は「どう作るか（処理手順）」で書かれていることが多く、「何を守りたいか（不変条件・事前条件・業務ルール）」は手順の中に埋もれています。このサンプルは、設計書から守りたいものを取り出せるか、また設計書だけでは判断できない点を質問として出せるかを確かめるために作ったものです（公式資料ではありません）。

ドメインは [tour-env](../tour-env/README.md) と同じツアー予約です（`RESERVE.TRANSFER` は 0:未 1:済 9:取消）。tour-env の影響分析の評価に影響しないよう、別のフォルダに置いています。

## パターン

| パターン | ファイル | 埋もれているもの |
| --- | --- | --- |
| P1 手順型 | `docs/P1_処理設計書_予約取消.docx` | 番号付き手順の中の事前条件・状態遷移・不変条件 |
| P2 判定表型 | `docs/P2_取消料率表.xlsx` | 表の並びに隠れた単調性・境界・計算式 |
| P3 擬似コード型 | `docs/P3_処理設計書_予約入力チェック.docx` | IF文の分岐に隠れた事前条件・不変条件 |
| P4 運用手順書型 | `docs/P4_運用手順書_夜間ジョブ再実行.docx` | オペレーターへの指示に隠れた順序制約・冪等性 |
| P5 改訂履歴型 | `docs/P5_画面項目定義_予約入力.xlsx` | 本文は古く、改訂履歴にだけある現在の値（矛盾） |
| P6 曖昧・例外型 | `docs/P6_処理設計書_予約変更.docx` | 副作用として書かれた原子性、条件の無い例外 |

意図的に入れた「質問にすべき点」もあります。

- 本文と改訂履歴の値の食い違い（P5）
- 文書をまたいだ矛盾：予約の受付期限と支払期限（P3 と P5）
- 条件の書かれていない例外（P6）
- どのテーブル定義にも無い列への依存（P4 と tour-env の設計書）

## 使い方

```bash
python samples/spec-extraction/make_docs.py                 # 設計書を生成（docs/ にコミット済み）
# eval/spec_extraction/prompt.md の指示でエージェントに抽出させ、結果を JSON で保存する
python eval/spec_extraction/score.py result.json --detail   # 正解と照合する
```

正解は [eval/spec_extraction/ground_truth.json](../../eval/spec_extraction/ground_truth.json)（ルール20件、質問7件。うち質問3件は初回の評価でエージェントが見つけた、題材作成時に意図せず入った矛盾・定義漏れ）にあります。採点は語のゆるい一致なので、最終的な判断は `--detail` の対応表を人が見て行ってください。

## 注意

- 設計書の内容は検証用に作ったもので、TERASOLUNA のツアー予約アプリの実装とは一致しない箇所があります。実装との照合（設計書にあって実装に無いルールの検出）を試す場合は、その前提で結果を見てください。
